# J2. Синхронизированный доступ к списку

В работе сделаны две реализации: свой односвязный список с блокировками узлов и `ArrayList` с обёрткой `Collections.synchronizedList`. Обе используют один и тот же класс `Sorter`

Основной поток читает строки и добавляет их в начало списка. Каждая дочерняя нить непрерывно выполняет пузырьковую сортировку в лексикографическом порядке. Пустая строка выводит текущее состояние списка и общий счётчик шагов

Используются Java 21, Gradle и JUnit 5.11.4

## Запуск

Открыть папку `J2` как Gradle-проект, выбрать Java 21 и запустить класс `ru.nsu.vorona.Main`

Аргументы:

```text
linked 3 100 100
```

| Аргумент | Значение в примере |
| --- | --- |
| Реализация | `linked` — свой список, `sync` — стандартный |
| Количество сортирующих потоков | `3` |
| Задержка внутри шага | `100` мс |
| Задержка между шагами | `100` мс |

Для стандартного списка:

```text
sync 3 100 100
```

В консоли вводятся строки, например `zebra`, `orange`, `apple`, `banana`, каждая с новой строки. Пустая строка показывает список. Вывод может быть частично отсортированным: потоки продолжают работу после печати. После этого можно добавить ещё строки и снова вывести список

Строки длиннее 80 символов разбиваются на части до 80 символов. Каждая часть добавляется в голову списка отдельно. Конец ввода завершает программу и останавливает сортирующие потоки

## Синхронизация

В своём списке каждый узел содержит строку, ссылку на следующий узел и `ReentrantLock`. Дополнительно есть служебная голова без строки

Для перестановки соседней пары захватываются три узла: предыдущий и два сравниваемых. Блокировки всегда берутся от головы к хвосту. Меняются ссылки, содержимое строк между узлами не обменивается. Весь список на время сортировки не блокируется

Задержка внутри шага выполняется с удержанием трёх блокировок. Поэтому другие потоки могут работать с непересекающимися тройками, но должны ждать, если им нужен занятый узел. В `sync` внутреннюю задержку и обмен защищает `synchronized (values)`: одновременно выполняется только один шаг. Одних синхронизированных `get` и `set` недостаточно, поскольку вся последовательность чтения, сравнения и обмена должна быть атомарной

Задержка между шагами находится в `Sorter`, после возврата из `stepAt`. В этот момент поток уже освободил блокировки. При одном сортирующем потоке ввод и вывод в этот период не ждут окончания задержки. При нескольких потоках может потребоваться дождаться другой нити, которая выполняет свой защищённый шаг

Обе реализации реализуют `Iterable`, печать выполняется через `for-each`. Итератор обходит снимок списка. В своём списке снимок строится с последовательным захватом узлов, а в `sync` — под монитором списка. Это сохраняет количество и содержимое записей при одновременной сортировке

После завершения ввода сортирующие потоки получают `interrupt`. Ожидание блокировок в своём списке прерывается через `lockInterruptibly`, захваченные блокировки освобождаются в `finally`

## Подсчёт шагов

Шаг — сравнение существующей соседней пары, независимо от того, понадобился обмен или нет. Проверка за концом списка шагом не считается. Сортировка всегда проходит весь список, в том числе уже отсортированный

Пусть `n` — постоянное число строк, `k` — число потоков. Один полный проход даёт `n-1` шагов. Если каждый поток сделал `p` полных проходов без остатка, суммарно получится:

`S = k*p*(n-1)`

Если потоки сделали разное число проходов, для каждого отдельно считаются полные проходы и шаги последнего незавершённого прохода, затем результаты складываются

Для оценки за время `T` мс обозначим внутреннюю задержку через `a`, задержку между шагами через `b`. В нашей реализации после последней пары есть ещё проверка конца списка. Внутренней задержки у неё нет, но после неё тоже выполняется задержка `b`. Поэтому время полного прохода без ожиданий и накладных расходов:

`P = (n-1)*a + n*b`

При независимой работе потоков оценка числа шагов:

`S0 = k*T*(n-1)/P`

Для `linked` нужно учесть, что две одновременно занятые тройки не должны пересекаться. Всего есть `n+1` узел со служебной головой, поэтому одновременно могут быть заняты не больше `m = floor((n+1)/3)` троек. При `a > 0` оптимистичная верхняя оценка для длительного запуска:

`S_linked <= min(S0, m*T/a)`

Для `sync` одновременно занят только один монитор, то есть выполняется не больше одного защищённого шага. При `a > 0`:

`S_sync <= min(S0, T/a)`

При `a = 0` используется `S0`. Формулы описывают идеализированный темп работы, а не точное число за короткий интервал: они не учитывают начало и конец измерения, переключения потоков, точность задержек, обход списка и ожидание блокировок

## Замеры

Для измерений запускается `ru.nsu.vorona.BenchmarkMain`. Аргументы: число строк, число потоков, время для каждого режима в мс, внутренняя задержка и задержка между шагами

```text
20 3 5000 10 10
```

Программа создаёт обратный отсортированному список, отдельно запускает оба режима и после остановки потоков выводит число шагов

Параметры измерений: 20 строк, 5 секунд на каждый режим, задержки 10 + 10 мс. Среда: Linux, Java 21.0.13

| Потоки | Оценка linked | Измерено linked | Оценка sync | Измерено sync |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 244 | 241 | 244 | 241 |
| 3 | 731 | 486 | 500 | 493 |
| 6 | 1462 | 562 | 500 | 490 |

При одном потоке результаты близки к оценке: конкуренции за блокировки нет. При нескольких потоках `sync` приближается к пределу `T/a = 500` шагов. Пока один поток спит внутри шага, остальные ждут монитор

Свой список позволяет работать параллельно, но ускорение не равно числу потоков. Все потоки начинают у головы, конкурируют за соседние узлы и при поиске каждой пары снова идут от головы. Занятый узел на пути задерживает дальнейший обход. Поэтому в запуске с тремя потоками `linked` немного уступил `sync`, а с шестью выполнил больше шагов, но намного меньше оптимистичной оценки. Результаты повторных запусков могут отличаться

## Тестирование

Запуск из папки `J2`:

```text
gradle test
```

Семь тестов проверяют вставку в начало, перестановку соседей, доступ к списку между шагами, удержание блокировок внутри шага и их освобождение при прерывании

Отдельно проверяются параллельные шаги на разных участках связанного списка и последовательные шаги стандартного списка. В проверке вставки во время сортировки работают четыре потока, итоговый список должен содержать 200 различных строк в отсортированном порядке
