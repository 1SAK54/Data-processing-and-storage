# J3 — Асинхронный обход ресурсов HTTP-сервера

Программа на Java 21 обходит ресурсы сервера, начиная с `/`, и печатает полученные значения `message` в лексикографическом порядке. Все найденные пути `successors` обрабатываются в виртуальных потоках. Повторные адреса пропускаются.

## Требования

- JDK 21 или новее;
- Gradle 8.5+ (либо Gradle, доступный через IntelliJ IDEA);
- доступ к Maven Central при первой сборке (Jackson и JUnit).

## Сборка и тесты

В корне проекта:

```powershell
gradle clean test
```

## Проверка на сервере из задания

В одном терминале (из корня проекта):

```powershell
java -jar Task_J3-server.jar VoronaMikhail
```

Во втором терминале:

```powershell
gradle run
```

Для другого порта клиента:

```powershell
gradle run --args="http://localhost:3000/"
```

Результат выводится в stdout, по одному сообщению на строку. В случае сбоя программа завершается с исключением, а в подавленных исключениях (`suppressed`) перечислены ошибки отдельных запросов.

## Структура

- `Main` — аргументы запуска и вывод результата;
- `HttpSpider` — планирование запросов и сбор сообщений;
- `ServerResponse` — модель JSON-ответа;
- `HttpSpiderTest` — 12 интеграционных тестов с локальным HTTP-сервером.

## Как работает синхронизация

- `ConcurrentHashMap.newKeySet()` хранит URL, уже поставленные на обработку, и предотвращает повторный запрос;
- `ConcurrentLinkedQueue` собирает сообщения и ошибки из параллельных задач;
- `Phaser(1)` учитывает основную нить. Для каждого нового URL вызывается `register()` **до** отправки задачи; после её выполнения — `arriveAndDeregister()`. Основная нить ждёт через `arriveAndAwaitAdvance()`;
- виртуальные потоки позволяют одновременно ожидать медленные ответы сервера без выделения системной нити на каждый запрос;
- сортировка выполняется только после окончания обхода.

## Ограничения и замечания

Задание гарантирует HTTP 200 для допустимых путей и задержку ответа до 12 секунд. На каждый HTTP-запрос установлен тайм-аут 30 секунд. Ограничение времени полного обхода не вводилось: время 120 секунд в задании описывает возможности сервера, а не отдельный тайм-аут клиента. Для недопустимых путей и некорректного JSON выводится ошибка. Встроенные тесты не заменяют проверку на персональных данных предоставленного JAR.
